# Imported magnetic maps, 2026-10-24

These are actual release-test flights on Ryzen 9 5950X under WSL2, not
extrapolations or a SIMION timing comparison. The manufactured exports are
generated by `crates/simrep-fly/tests/bfield_import.rs`, then parsed and
reconstructed through the public import API. The Cartesian tests independently
write generic CSV, Opera header-block tables, COMSOL Spreadsheet and COMSOL
Grid. All four recover the same nodal vectors and give the same endpoint/TOF
errors below. Axisymmetric tables independently export axial B and Br.
All 57 measured records are retained in `bench/bfield-import-20261024.csv`;
blank orders mean no coarser reference or a roundoff-floor error. Every
timing record is explicitly marked `contended=true`.

The exact and re-imported fields fly the same ion with the same RK45 settings:
1e-12 tolerances, 0.05 us ceiling, a detector at x=1.4 mm, and a 5 us safety
duration. Every flight reaches the detector with the same termination reason.
The solenoid is the exact sum of 16 thin Biot-Savart hoops, not the optional
calibrated CPU coil map. The sector uses a source-free analytic 1/r tangent
field in 2D, extended along the third Cartesian axis.

## Timings and contention

**Contended, single-flight diagnostic timings**, not an isolated performance
benchmark. Before these runs, process inspection showed another
`simrep_fly` test process using 265% CPU and an Opera automation runner using
12%; the RTX 3070 utilization query was 0%. Other builds/tests were allowed to
resume after the shared quiet window. The following records separate parsing
and C2 construction from integration. Export generation is excluded.

| Loop, CSV 3D | 25.4567 | 2.5471 | 0.0387 |
| Solenoid, CSV 3D | 24.2401 | 2.6052 | 0.2656 |
| Sector, CSV 3D | 20.8265 | 2.5016 | 0.0161 |

| Loop, axisymmetric | 0.8791 | 0.4231 | 0.0363 |
| Solenoid, axisymmetric | 1.0710 | 0.4460 | 0.2442 |

For these short, simple analytic controls the imported map was slower than
exact evaluation. This table establishes import cost and correctness, not a
speedup over exact toy fields or SIMION. No measured magnetic GPU crossover
is enabled; `--device auto` stays CPU.

Reproduce all records with:

```bash
cargo test -p simrep-fly --release --test bfield_import -- --nocapture
```

The separate `gpu_imported_magnetic_maps_precise_and_preview` regression checks
3D/axisymmetric upload, both precisions, reflected root frames, rotated/scaled
maps, all three outside policies, multiple maps and coil/uniform superposition.
Linux software Vulkan passed both precision paths (one test, 106.18 s).
Windows Vulkan selected **NVIDIA GeForce RTX 3070** and passed the same test
in **7.04 s** on the final replay, with `Precise: f64=true` and
`Preview: f64=false`.
The test executes both dimensionalities and all three outside policies in
each precision, comparing every endpoint, velocity and TOF against CPU
flights (3e-9 f64 and 3e-4 Preview component tolerances). These durations
include shader/pipeline work and are not flight-kernel timings.

Windows `gpu-info`/`gpu-smoke` also completed on both documented backends.
DX12 passed f32 (maximum absolute residual discrepancy 5.364418030e-7);
native f64 was explicitly unavailable. Vulkan passed f32 with the same
discrepancy and f64 with zero discrepancy for the smoke fixture. These are
the existing 64^3 residual checks, not imported-map flight error measurements.

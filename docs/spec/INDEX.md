## Important gap

The CHM is the *Supplemental Documentation*, not the SIMION User Manual. Several core specs
are only referenced, never reproduced: the byte layout of the base PA header ("Files Used by
SIMION" appendix, F.5 in the 8.0 manual), the full FLY2 grammar (FLY2 appendix), the GEM
appendix (but its 8.1 reference *is* reproduced in `gem_geometry_file.html`), the Refine
chapter (ch. 6), the Computational Methods appendix (integrator and T.Qual formulas, H.23), and
the full command-line option list (Appendix M). No copy of the User Manual PDF exists under
`[install]`. Where the manual is missing, the most precise in-CHM sources are the SL library
reference pages (`python_simion.pa.html`, `cpp_simion.pa.html`, `perl_simion.pa.html`) and the
Lua API pages (`lua_simion.pas.html`, `lua_simion.wb.html`).

## Topics

| Topic | Files | Summary |
|---|---|---|
| PA file format | `potential_array.html`, `potential_array_types.html`, `writing_pa0_files.html`, `anisotropically_scaled_pas.html` (section "PA File Format"), `antimirroring.html` (section "PA File Format"), `surface_enhancement.html` (section "PA Format"), `fast_scale_extension.html`, `python_simion.pa.html`, `cpp_simion.pa.html`, `perl_simion.pa.html`, `lua_simion.pas.html` | A PA is a 2D/3D rectangular grid storing, per point, a potential plus an electrode/non-electrode flag, preceded by a header (dimensions, symmetry, mirroring, field type, magnetic scaling `ng`). The CHM documents only deltas to the base layout: extra bit flags packed into the header's mirror word, a "mode -2" header variant that appends three doubles for per-axis cell size, the trailing block a `.PA0` carries (adjustable-electrode count, solution voltage, per-electrode first-point offsets, optional current values), the ASCII `.PA+` solution-sharing file, and `.pa-surf` surface data. The SL library pages (getters/setters and validators for every header field) are the best stand-in for the missing base spec. |
| PA symmetry/mirroring and grid units | `potential_array.html`, `antimirroring.html`, `neumann_boundary_conditions.html`, `pa_scaling.html`, `anisotropically_scaled_pas.html`, `surface_enhancement.html`, `faq.html` (grid scaling, off-by-one, nz=1 questions), `python_simion.pa.html` (`symmetry`, `mirror_x/y/z`, `dx_mm`...) | Symmetry (planar vs. cylindrical) and per-axis mirror planes are header properties; a mirror plane acts as a zero-normal-gradient boundary, and 8.1 adds anti-mirroring (sign flip across the plane, flagged by high bits of the mirror word). Physical size is the PA's own cell size in mm per grid unit (per-axis since 8.1, default 1) multiplied by a per-instance scale factor set on the workbench. Fractional grid units let electrode surfaces sit between grid points for better accuracy. |
| Refine algorithm and convergence settings | `refine.html`, `poisson_solver.html`, `calculation_time.html`, `accuracy.html`, `lua_simion.pas.html` (`pa:refine` parameters), `laplace_equation.html`, `poisson_equation.html`, `dirichlet_boundary_conditions.html`, `neumann_boundary_conditions.html`, `multicore.html`, `hpc_cluster.html`, `simion.html`, `dielectric.html` | Refine solves Laplace (or, since 8.1, Poisson) on the grid by finite differences with optimized over-relaxation and multi-mesh acceleration; electrode points are fixed (Dirichlet) values. It stops when no point changes by more than the convergence limit (volts/mags) in one iteration; `pa:refine` also exposes max iterations, max over-relaxation, a historical-memory factor, skipped-point mode, per-solution refine, RAM-only (`disk=false`) and resume. Multithreaded refine, splitting PA# solutions across machines, dielectrics and permeability are covered as enhancements. |
| `.fly2` particle definition format | `fly2_file.html`, `fly_file.html` (legacy `.FLY`), `ion_file.html`, `particle_initial_conditions.html`, `particle_gun.html`, `lambert_cosine.html`, `lua_simionx.Statistics.html` | A FLY2 file is Lua code that calls `particles { ... }` containing beam blocks (e.g. `standard_beam` with count, mass, charge, KE, direction, position, coordinates), where any parameter can be a `sequence{}` or a `distribution(fn)` backed by arbitrary Lua. The CHM page gives recipes (custom distributions, rejection sampling, dependent parameters, ellipses, parameter passing) but defers the base grammar to the manual. The simpler `.ION` alternative is a CSV with one particle per row: birth time, mass, charge, x, y, z, azimuth, elevation, KE, charge weight factor, color. |
| GEM geometry language | `gem_geometry_file.html`, `geometry_input_methods.html`, `pa_scaling.html` (`pa_define` with cell size), `surface_enhancement.html` (section "Usage / GEM files") | Full 8.1 syntax reference plus 8.2 additions. Structural keywords: `pa_define`, `include`, `electrode`/`e`, `non_electrode`/`n`, `fill`, `edge_fill`, `rotate_fill`, `rotate_edge_fill`, `within`, `within_inside`, `within_inside_or_on`, `notin`, `notin_inside`, `notin_inside_or_on`, `locate` (aliases `project`/`transform`). 2D primitives: `box`, `centered_box`, `corner_box`, `circle`/`ellipse`, `hyperbola`, `parabola`, `points`, `polyline`. 3D primitives: `box3d`, `centered_box3d`, `corner_box3d`, `cylinder`, `sphere`/`ellipsoid`, `points3d`. 8.2 adds `shape`, `intersect`, `revolve_xy/yz/zx`, `extrude_xy/yz/zx`, `scale`, `rotate_x/y/z`, `cylinder3d`, `half_space`, `stl`, `inf`, mm-based `pa_define`, implicit fill/within, `.wgem` workbench files, and a Lua-based macro preprocessor (variables, loops). |
| Fast adjust / electrode voltages | `potential_array_types.html`, `fast_scale_extension.html`, `writing_pa0_files.html`, `faq.html` (fast_adjust vs init_p_values vs Fast Adjust button), `lua_simion.pas.html` (`pa:fast_adjust`), `time_dependent_field.html`, `max_electrodes.html`, `ram_and_memory.html` | A `.PA#` marks electrodes by number instead of voltage; refining it writes one unit-voltage solution array per adjustable electrode (`.PA1`, `.PA2`, ..., plus `.PA_` for fixed electrodes) and a base `.PA0`. Fast adjusting rebuilds the `.PA0` as a voltage-weighted linear sum of those solutions, with no re-refine needed; `.PA+` lets several electrodes share one solution at fixed ratios. Time-varying voltages are done from a `fast_adjust` user-program segment; 8.1 allows up to about 1000 adjustable electrodes. |
| Ion flying: integrator, time step control, trajectory quality | `time_step_size.html`, `simion.html`, `accuracy.html`, `ke_error.html`, `particle_trajectory_calculation.html` (sections "Time step control", "Particle control"), `lorentz_force_law.html`, `omit_relativistic_effects.html`, `multiple_pas.html`, `time.html`, `calculation_time.html` | Trajectories are integrated with a Runge-Kutta scheme (exact order/formulas are in the manual's Computational Methods appendix, not here), including relativistic corrections unless disabled. Step length is expressed in grid units and set by T.Qual (-500..500, default 3): values of 0 or below give fixed steps of 1/(1+abs(q)) gu, 1..99 give 1 gu with adaptive shrinking near curvature, reversals, electrodes and PA boundaries (CV limit = 1/q), and 100..500 combine a smaller base step with adaptive shrinking. Time markers and a `tstep_adjust` segment can force further reductions; overlapping PA instances are resolved by instance priority. |
| Data recording | `data_recording.html`, `marker.html`, `test_plane.html`, `particle_trajectory_calculation.html` (sections "Count/detection", "Measure beam"), `field_io.html` (field-probing trick), `faq.html`, `excel.html` | Data Recording writes chosen per-particle quantities (TOF, position, velocity, KE, potential, field...) at chosen events (start, every step, splat, markers, etc.) to the log or a file, either verbose (labelled) or delimited (CSV). Markers come from recording events, periodic time markers, or `mark()` calls in user programs; test planes and Lua segments cover custom counting and statistics. The recording setup is stored alongside the workbench (`.rec`). |
| STL import and any CAD import | `sltools_stl.html`, `sltoolstut.html`, `sl_tools.html`, `geometry_input_methods.html`, `gem_geometry_file.html` (8.2 `stl` command), `surface_enhancement.html` (section "Usage / STL Files"), `quickfield.html`, `poisson_superfish.html`, `cfd.html` | The only CAD path is STL (binary or ASCII): SL Tools `stl2pa` (GUI or command line) voxelizes a chosen bounding region at a chosen grid size into a `.PA`/`.PA#`, with electrode numbering, dielectric and accuracy notes; since 8.2.0.10 GEM files can embed STL and mix it with GEM solids, with fractional-grid surfaces. 2D bitmaps (BMP/PNG/JPEG/PNM/GIF) can also become 2D PAs; there is no STEP/IGES/DXF import. Field maps from QuickField, Poisson Superfish and CFD codes come in through text conversion or Lua. |
| Export features | `data_import_export.html`, `field_io.html`, `data_recording.html`, `sltoolstut.html` (PA to text, PA to STL, CLI usage), `sl_tools.html`, `lua_simion.wb.html` (`simion.wb:save_stl`, `simion.wb:save`), `lua_simion.pas.html` (`pa:save`, `pa:potential_vc`, `pa:field_vc`), `movie_files.html` (stills, `simion.print_screen`), `excel.html`, `python_simion.pa.html` | Exports: trajectory data via Data Recording (text/CSV); whole PAs to ASCII text (`pa2text`), to STL (keeps symmetry by sweeping sectors) and 2D PAs to bitmaps via SL Tools; the whole workbench (PA instances plus trajectories) to STL via `simion.wb:save_stl`; potentials/fields at arbitrary points via the Lua `simion.wb`/`simion.pas` APIs (e.g. the field_dump example to CSV/Excel/gnuplot); native PA/IOB/FLY2 saving; screen images via print, Windows Metafile or `simion.print_screen`, and live Excel via COM. There is no built-in movie export (third-party screen capture is recommended). |
| Space charge / repulsion | `space_charge.html`, `charge_repulsion.html`, `poisson_solver.html` (sections "Computing charge density from trajectories", "Charge density smoothing"), `coulombs_law.html`, `current_density.html`, `thermionic_cathode.html` | SIMION ignores space charge by default and offers two remedies. Charge repulsion: Coulombic or Factor mode treats particles as time-stepped point charges or charge clouds (total charge in coulombs or as a multiplier), while Beam mode treats each trajectory as a steady line current in amps relative to a reference particle #1; each particle's share is scaled by its charge weighting factor. Alternatively the Poisson solver deposits charge density from trajectories into the PA and re-solves iteratively (e.g. for thermionic cathodes). |
| Collisions (HS1/SDS) | `ion_gas_collisions.html`, `collision_model_hs1.html`, `mobility_equation.html`, `cfd.html`, `particle_trajectory_calculation.html` (section "Collisional effects"); example code: `[install]/examples/collision_hs1/collision_hs1.lua` and `notes.pdf`, `[install]/examples/collision_sds/collision_sds.lua` and `collision_sds_documentation.pdf` | Collisions are not built into the core; they are Lua user programs that modify motion each time step (`other_actions`/`accel_adjust`). HS1 models elastic hard-sphere collisions with a neutral Maxwell-Boltzmann background gas (optionally drifting, so it can both cool and heat ions); SDS targets near-atmospheric pressure by combining mobility-based viscous drift with statistically sized random jumps instead of individual collisions; Stokes drag is the simplest option. Gas flow fields are not solved (no CFD) but can be supplied as arrays or equations. |
| Magnetic fields | `magnets.html`, `magnetic_potential.html`, `permeability.html`, `biot_savart_law.html`, `lua_simionx.MField.html`, `lorentz_force_law.html`, `helmholtz_coil.html`, `solenoid_magnetic_field.html`, `magnetic_sector.html`, `anisotropically_scaled_pas.html` (section "Effect on Magnetic Arrays (ng Scaling Constant)"), `poisson_solver.html` (section "Comments on magnetic arrays") | Three ways to define a B field: a magnetic scalar-potential PA (units "mags", poles treated as infinitely permeable, refined like an electrostatic PA and scaled by the header constant `ng`); a vector-potential PA solved with currents and finite permeability through the Poisson solver (8.2/experimental); or field vectors supplied directly, e.g. analytically in an `mfield_adjust` segment or from Biot-Savart current paths via `simionx.MField`. Electric and magnetic PAs can overlap, and the particle sees the Lorentz force from both; quasi-static only (no induction). |
| Command line / `--nogui` batch options | `command_line_interface.html`, `refine.html` (RAM-only example), `hpc_cluster.html`, `linux.html`, `multicore.html`, `lua.exe.html`, `lua_simion.html` (`simion.command`), `calling_external_programs.html`, `sltoolstut.html` (section "Advanced: Command-line Usage"), `faq.html` | The general form is `simion.exe --nogui [--noprompt] [--quiet] [--lua <code or @file>] <command> ...`, with commands such as `fly <iob>` (`--remove-pas`, `--disk`, `--refine-convergence`), `refine <pa#>` (`--convergence`, `--resume`) and `lua <script>`. The same command strings can be run in-process from Lua via `simion.command()`. The full option list is in manual Appendix M (not in the CHM); SL Tools has its own CLI (`sltools [--nogui] stl2pa|bitmap2pa|pa2text|text2pa|view ...`). |
